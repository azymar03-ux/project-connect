# Security and abuse threat model
9 October 2026 · engineering analysis, not an independent penetration test

## Boundaries and protected data
The browser is untrusted; the API enforces authorization using opaque, hashed sessions and current database relationships. Public profiles/projects/resources/stores are not confidential. Direct messages, workspace files/chat, private AI history, credentials, outbox content and quota identities are protected data. A block is not secrecy from a logged-out visitor and does not revoke shared project membership.

| Threat / boundary | Implemented control | Local evidence | Residual / operational gate |
|---|---|---|---|
| Account pre-hijacking and enumeration | Neutral production registration, quarantined pending identity, mailbox-chosen fresh password, grant cleanup, one-use hashed action tokens, request floors, exact origins | Activation/recovery/browser and provider HTTP suites | Statistical timing/abuse testing; live deliverability; independent account-recovery review |
| Credential/session theft and confused deputy | HttpOnly/Secure production cookie, SameSite=Lax, exact origin checks, revocation, current object access checks, no email-only Google linking | Secure cookie in real Chromium local TLS; signed Google fixtures | Public TLS, reverse-proxy trust, secret rotation and live callback deployment |
| Object-level authorization / concurrency | Ordered user/project locks; capacity transactions; task versions; scoped downloads/cursors; post-fetch GitHub membership/link/grant checks | Membership/removal/upload/block/AI deletion/cursor tests | Independent multi-replica testing; requests committed before revocation cannot be undone |
| Chat ambiguity / cross-conversation disclosure | Scoped random request IDs, same-ID/content conflict, metadata-only 24h browser recovery, generation guards, shared in-flight ownership, explicit retry; signed deletion-independent position cursors | Offline/reload/switch/back/late-completion/read-status and backend tests | Text deliberately not stored offline; no guaranteed delivery after browser data loss; polling, not realtime |
| Malicious uploads | Auth before multipart; size/type/UTF-8 limits; image decode/re-encode/dimension limits; random private keys, safe content disposition, durable cleanup markers | File/image/cleanup/race/browser tests | No antivirus claim; sandbox decoder CPU/memory and live S3 lifecycle need load/provider testing; users must treat downloads as untrusted |
| SSRF / provider escalation | Closed HTTPS host/path adapters; no submitted URL fetching; redirect refusal/timeouts/body bounds; public GitHub requests have no private credential; scoped ephemeral App tokens | Provider protocol/HTTP, quota/cache/revocation fixtures | Live provider grants, DNS/egress policy, restrictive cloud firewall and billing settings |
| Prompt injection / model misinformation | No tools, secret access, team-file retrieval or code execution; schema validation and explicit roadmap import confirmation; links labeled unverified | Assistant/schema/cancel/backpressure/HTTP fixture tests | Model quality evaluation and approved privacy/retention; not certified electrical/drone advice |
| Cost exhaustion / Sybil abuse | Shared Redis rate limits; service/user/project AI reservation ledger, conservative token budgets survive deletion; bounded streams and quotas | Atomic limit/outage/ledger/cancel tests | Tokens are not price-denominated dollar caps; provider hard budgets and multi-account abuse operations remain necessary |
| Ranking privacy and manipulation | Only explicit skills/interests/city and visible public activity; no private messages, online presence or inferred sensitive traits; capped activity bonus; signed filter/time-bound cursors | Deterministic SQL/JS parity, visibility, tamper/profile-binding fixtures | Heuristic not predictive probability; adversarial profile gaming and product-quality evaluation with consenting users |
| Availability / recovery | Queue retry/leases, fail-closed Redis, bounded telemetry, monitor exit codes, 40-table local restore and authenticated byte checks | Monitor mocks + real admin/nonadmin HTTP; restored compiled API | Off-site encrypted DB+files retention, key escrow, restore time/RPO, monitoring alert delivery and host failure drills |

## Logging policy
Log fixed error codes and route templates, never raw auth headers, OAuth query codes, private payloads, prompt text, mail bodies, storage keys, database URLs or provider tokens. Admin operations returns aggregate counts; monitor validates a fixed alert-code vocabulary. Source scans are limited credential signatures, not a substitute for a secret scanner and history review. Do not ship `.arena`, `.env.production`, private files, test certificates or fixture sessions.

## Release rule
Zero known failing automated checks is necessary but insufficient. Keep live provider features disabled until owner-approved keys, grants, terms and budgets are configured and the actual hosted flow passes. Enforce least-privilege production DB/storage/network roles; never seed demo identities into production. Independent security review, manual assistive-technology testing and actual deployment remain explicit launch gates, not work silently marked complete.
