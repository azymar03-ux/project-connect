5Uploading an image (avatar / project photo)

The most mysterious feature for beginners — here is every gate it passes:

Pick file in the upload boxImageUpload.tsx checks type + size, sends immediatelyPOST /api/account/avatar (or projects/…/images)
↓server never trusts the client
Magic-bytes recheck + real image dimensionsa .jpg renamed from .exe dies here
↓
Temp file → ClamAV scanpersistently queued so a crash can’t skip it
↓
Infected / failed → 400never stored, never served
Clean → durable storage + SHA-256 digestDB links it: avatarId / project imageId
↓
Client refetches → gets the server URLGET /api/images/:id (audience-checked)
↓
PreviewImage renders: loading · OK · failed + Retry“still scanning” or “quarantined” shows a clean message, never a broken-image icon
Beginner insight: the thumbnail you picked lives only in your RAM. What you see after saving always comes back from the server. So a “preview not working” report means: check upload response, then /api/images/:id status, then cookie/origin — in that order.

Files: apps/web/app/components/ImageUpload.tsx, PreviewImage.tsx · apps/api/src/features/images.ts · apps/api/src/core/file-scanner.ts, storage-scan.ts, public-image.ts
