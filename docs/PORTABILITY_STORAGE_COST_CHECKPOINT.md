## Implemented + locally verified
- **Portability:** durable asynchronous ZIP queue; database-wide one-builder lease; attempt fencing; repeatable-read snapshot of all 23 owner-scoped sections; immutable object pins; bounded streaming ZIP output; exact-byte SHA-256 manifest and artifact digest. API and Settings request/status/download/cancel controls. Requesting session must remain valid during build and download; other users cannot retrieve/cancel. Three requests per rolling day, including cancellation tombstones; 24h expiry; 1,000 active queue ceiling.
- **Portability safety:** files only for the requester's uploads in current memberships at snapshot time; avatar and owned covers. No received/private third-party message bodies, password/session/OAuth secrets or private storage keys. NDJSON section entries and ID-based attachment paths, never caller filenames as ZIP paths. Snapshot pins protect bytes after metadata retirement; cleanup resumes after pins release. Revocation, expiry, cancellation, foreign audience, 205-row section and delete-after-snapshot tests pass. Limits: 64 MiB metadata, 256 MiB ZIP, 10,000 objects, 60s DB snapshot, 120s build deadline. Larger exports fail explicitly; paged exports remain as fallback. Unknown legacy object-key formats fail safely rather than traversing storage. Not unlimited-volume portability or an S3-certified worker.
- **Storage:** safe inventory CLI, dry-run by default; paged local/S3 inventory, no symlink traversal; only recognized immutable keys older than 48h can be queued by explicit `--apply`; existing cleanup rechecks references/pins. Unknown names are counted, never deleted. Object PUT now has a timeout/no-overwrite condition and failed upload retains late-PUT cleanup grace.
- **Scanning:** bounded clamd INSTREAM adapter on attachment/avatar/cover uploads, no shell/file paths; production rejects absent scanner, infection, error, truncated response or timeout. Development no-scanner behavior is explicit. Private Compose scanner service supplied and YAML parsed. Protocol tests preserve bytes and reject invalid outcomes. **No actual ClamAV engine/signature database, container or S3 scanner test was executed.** Existing unscanned legacy content needs inventory/rescan/quarantine follow-up.
- **AI dollar control:** integer microUSD reservation ledger; conservative per-row greater-of-booked/current price sum, ceil rounding, atomic user/project/global cost checks under existing durable advisory lock. Provider enablement/price changes cannot make token-only legacy usage free. No refunds on failure/cancellation/unknown usage. Actual usage above token reservation increases booked amount; overrun still warrants alert/provider review. Production live AI requires explicit model-to-pricing approval, ceiling and all budgets. Ceiling must cover input/output/reasoning token rates and does not assert a current vendor price. Separate token/request caps remain. Mixed-price aggregate undercount regression covered.
- **SEO:** public project/profile sitemap index and ID-range partitions instead of silent 1,000-project cutoff. 10,000-entry initial partitions, max 45,000 entries after growth, index max 50,000 URLs; oversize/unavailable produces 503 rather than falsely complete XML. Visibility filters apply on each read. Boundaries can shift with edits; public sitemap cache is 5 minutes, not instantaneous revocation.
- **Contracts:** pure Zod wire contracts consumed by API and browser for portability, roadmap request and sitemap partition. Deterministic generated backend copy keeps API deployment layout; `contracts:check` prevents drift. OpenAPI registered-route inventory: **111 paths / 137 operations**; detailed payload schema coverage is partial, explicitly labeled. Full typed client migration is still unfinished.
